## 1  产品结论与已确认边界

产品定位为本地优先的重要日期管理 App。用户用不同的本整理生日、纪念日、假日和目标，以最多三层事件连接重要节点，通过周期提醒、背景和一段事件寄语，持续记得并期待这些日子。目标事件另有行动记录。

产品长期采用单设备本地资料库，启动后直接使用。不做登录注册，不规划云数据库或账号体系，也不采集邮箱。因此没有邮箱验证码、全局账号唯一性、跨设备自动同步及在线共同编辑。换机采用手动备份迁移。

| 状态 | 产品决定 |
| --- | --- |
| 已确认 | 生日逐年循环，默认提前 7 天及当天提醒；当天显示今天生日，次日显示下一次生日。 |
| 已确认 | 支持生日本、纪念日本、假日本等分组；首页默认展示最近事件，也可由用户指定。 |
| 已确认 | 子事件手动创建；主事件为第一层，最多三层；本不计入层级。 |
| 已确认 | 每层事件均可独立设置日期、背景、寄语和提醒；只保留一段可编辑寄语。 |
| 已确认 | 目标支持阶段目标与行动记录；支持文本文件导入导出、分享卡片、组件和日历关联。 |
| 已确认 | 长期保持本地存储；不做登录注册，不规划云数据库、邮箱认证或账号体系。 |
| 本稿建议 | 单一本地资料库、全量加密备份、30 天回收站、阶段完成状态和具体交互规则。 |

本稿建议是可评审的默认设计，不等于已获得用户逐项确认。平台、最低系统版本、最终视觉风格和发布安排仍需在实现前确定；不影响本次产品和需求规则的完整表达。

## 2  无账号产品与本地存储决策

不做登录注册是长期产品决定，不是等待获得云资源后补齐的功能。用户的日期管理、情感纪念与目标记录均发生在本机，账号没有提供数据同步、恢复或共同编辑的实际价值，因此移除整个账号体系。

| 用户需要 | 本地实现 | 边界 |
| --- | --- | --- |
| 开始使用 | 直接创建事件或导入备份 | 不注册、不登录、不采集邮箱 |
| 区分记录 | 资料库和事件使用随机 UUID | 标识记录，不表示在线用户身份 |
| 保护隐私 | 可选应用锁及系统安全存储 | 本地解锁，不含账号密码或邮箱找回 |
| 换机迁移 | 完整备份导出与新设备导入 | 无自动恢复，备份之外的新内容不能找回 |
| 分享日期 | 纪念日图片或文本文件副本 | 接收后独立保存，没有在线共同编辑 |

删除账号相关入口与流程，包括注册、登录、退出登录、忘记账号密码、邮箱验证码、邮箱唯一性校验、账号绑定、账号注销和跨账号切换。保留清空本机资料库，其含义是删除本地数据，不使用账号注销的文案。

以 library_id 标识本地资料库，以随机 UUID 标识事件。标识可随备份迁移，作用是维持引用与导入映射；不预留账号归属、登录会话或业务云同步接口。离线资料格式版本仍须保留，以支持未来本地升级。

应用锁口令和备份口令分别服务于本机隐私与文件保护，不应称为登录密码。忘记应用锁口令时按本地解锁及已有备份规则处理；没有服务端可找回数据，也不设置邮箱恢复通道。

资源投入集中在移动端、日期正确性、提醒适配、数据安全和发布测试。后续演进继续围绕离线使用、备份兼容、组件和展示体验开展，不将云数据库或账号服务列入路线图。

## 3  目标用户与产品价值

核心用户是需要记住亲友生日、纪念日和个人计划，同时希望用较轻的方式记录感受的人。第一使用场景是生日与纪念日；旅行、假日和阶段目标作为同一日期结构的延伸。

| 用户场景 | 关键任务 | 完成标准 |
| --- | --- | --- |
| 亲友生日 | 一次录入，逐年循环并提前准备 | 无需每年重建，日期和提醒可信 |
| 关系与纪念 | 持续正数，手动添加有意义的节点 | 每层有背景和寄语，层级容易找到 |
| 假日与旅行 | 查看最近期待的事情并制作卡片 | 首页与组件直观，导出内容可控 |
| 考试与个人目标 | 安排阶段日期并记下行动 | 阶段状态清晰，记录不依赖网络 |
| 换机与留存 | 把资料完整带到新设备 | 通过备份可恢复结构、文字及背景 |

产品的差异重点是本与三层手动事件的组织能力，以及每个事件同等完整的展示和记录能力。其价值是把生日、目标和回忆放进同一个容易理解的日期体系。该定位属于产品判断，尚需通过原型测试验证。

### 设计原则

- 准确和可靠优先。先让日期、循环和恢复规则可解释，再增加装饰性表现。

- 创建保持简短。标题、日期即可保存，农历、重复、提醒等按场景给默认值。

- 层级有边界。最多三层，子事件独立计算，日期与完成状态不隐式联动。

- 内容属于用户。业务功能断网可用，导出前说明范围，导入前预览变化。

- 状态诚实。区分提醒已开启与已安排，区分卡片分享、文件副本与实时共同使用。

第一版不设强制社交、动态社区、连续签到、AI 内容生成或付费限制；商业模式待验证后另行定义。

## 5  发布范围与完整交付顺序

P0 为用户核心诉求与数据安全所必需，P1 为本次要求覆盖的基础增强能力；两者都属于目标版本范围，可分阶段完成。P2 属于明确未承诺的扩展。若压缩首发范围，须明确列出未完成项，不能把阶段性版本称为需求全部完成。

| 阶段 | 交付范围 | 退出条件 |
| --- | --- | --- |
| 阶段 A  本地核心 | P0：本、三层事件、寄语背景、正倒数、公农历、生日循环、首页、搜索、默认提醒、应用锁、回收站、完整备份恢复 | 日期与树结构正确，数据迁移及故障回滚通过 |
| 阶段 B  完整体验 | P0：阶段目标、行动记录、文本文件、分享卡片、桌面组件；P1：标签批量、日历视图、日历关联、日期工具、可用平台的锁屏组件 | 满足对应功能验收，权限拒绝仍能使用核心 |
| 阶段 C  发布验证 | 真实设备提醒、长时间离线、权限变化、组件刷新、迁移、无上传检查、可访问性和性能 | P0 无阻断缺陷，P1 范围逐项验收 |

本地通用功能不依赖网络。日历中的外部账号同步、操作系统备份、用户把导出文件发到邮件或网盘，属于另外的数据出口。所有自动关联默认关闭；用户启用前明确告知接收方和数据范围。

### 不设网络服务依赖

- 不依赖邮箱、短信、推送服务器、远端数据库、远端图片存储或在线配置。

- 预设背景和基础节日模板随安装包提供。任意法定调休表必须有来源与覆盖年份，缺失年份明确标注未知。

- 不引入远端分析与崩溃上报 SDK；诊断只保存在本机，用户可主动导出脱敏报告。

平台与最低系统版本尚未指定。本稿同时给出 iOS 和 Android 规则，但每个发布包只能宣称已经实机验收的平台能力，不能直接假设所有系统都支持相同组件或提醒方式。

## 6  信息架构与关键页面

建议底部导航采用首页、日历、我的三个入口。首页含本的筛选与全部本入口，减少一个专门的分类页面层级。全局新增按钮从当前上下文预填本与父事件，始终让用户看见保存位置。

| 页面 | 主要内容与操作 |
| --- | --- |
| 首次使用 | 本地保存说明、创建事件和导入备份；不索取邮箱，不强制请求权限 |
| 首页 | 重点卡片、最近事件、固定事件、按本筛选、搜索与新增 |
| 全部本与本详情 | 创建和编辑本、管理顺序、查看本内树、批量归档及导出 |
| 事件详情 | 背景与日期、寄语、层级路径、直属子事件；目标事件显示阶段和行动 |
| 创建与编辑 | 标题、日期、类型、重复、提醒、背景、寄语及高级设置 |
| 日历 | 月视图和当天列表、跳转事件、查看循环发生日 |
| 分享与迁移 | 卡片预览、文本副本、完整备份、导入预览及结果 |
| 我的 | 本地资料库、备份状态、提醒诊断、应用锁、主题、数据清理与帮助 |

详情优先显示当前事件，不把整棵树无限展开。直属子事件可展开一层；到第三层隐藏新增子事件入口。路径显示所属本和父事件，使用户知道自己在哪里。搜索结果和首页若显示子事件，应同时显示父级路径。

视觉建议采用数字层级清晰、背景适度遮罩、文字对比充分的卡片。背景以日期可读为前提，寄语可留空；不以复杂动画作为识别事件的必要方式。最终配色、品牌名和插画风格由原型验证后确定。

## 7  关键业务体验与默认规则

### 周期生日

生日保留原始日期及日历类型。当天显示今天生日，直到该日结束；次日自动计算下一次生日。未知出生年份时不推算年龄。默认提前 7 天和当天当地时间 09 点提醒，可更改。晚于提前提醒时间才创建时，不补发过时通知。

### 三层手动事件

本不计层级。主事件为第一层，最多到第三层；每层字段一致。子事件允许早于或晚于父事件，父事件改日期不会修改子事件。移动子树前校验总深度与循环引用。删除或归档父事件涉及整棵子树时，先显示范围并确认。

### 首页与到期处理

自动模式以当天优先、下一发生日期升序排列；用户可以固定主卡片或将事件加入置顶区。默认只把主事件纳入最近列表，子事件可选择在首页显示。过期的一次性倒数保留为已到期，移到过去分区；纪念正数持续展示已过天数。

### 寄语与目标

每个事件只有一段寄语，可编辑或清空，不新增纸条列表或寄语历史。行动记录只属于目标管理，可多条、带日期、可编辑删除。阶段目标通过子事件表达；完成父目标不会自动完成子目标。

### 数据分享

卡片是一张生成时刻的静态图片；文本导入生成独立副本。完整备份用于迁移本、事件树、寄语、背景、行动记录和可迁移设置。不复制旧设备的通知任务、日历绑定和权限，恢复后按新设备重建。

## 8  本地架构与数据责任

建议使用本地关系型数据库保存结构化记录，应用私有目录保存背景文件，系统安全存储保存资料库密钥。日期引擎统一给首页、详情、卡片、日历和组件供数；设备通知与日历是受权限控制的系统适配层。此为实现方向，不限定最终跨端框架。

| 数据 | 默认位置 | 迁移方式 |
| --- | --- | --- |
| 本、事件、寄语和行动 | 本地数据库 | 完整备份；文本文件仅选定字段 |
| 背景与裁剪参数 | 应用私有文件目录 | 完整备份包含素材与参数 |
| 隐私与通知设置 | 本地设置和系统状态 | 偏好可迁移，权限须重新请求 |
| 应用锁密钥与口令校验 | 系统安全存储 | 不直接复制设备密钥；新设备重新设锁 |
| 邮箱账号与在线会话 | 本版不存在 | 无 |

备份是核心能力而不是附属入口。手机损坏、卸载或清除数据后，若没有可用备份，应用无法从服务器找回。修改数据后在本机标记未备份，重要批量操作前提示先导出；提示可稍后处理，不阻止日常使用。

不主动上传不等于能控制操作系统的一切。实现应配置可用的系统备份排除，并测试云备份和设备迁移；苹果明确排除标记并非绝对保证，Android 部分厂商的设备迁移也不同。对外承诺为应用不提供云同步、不主动上传业务数据，不能承诺系统恢复后一定为空。见 S13 与 S14。

用户启用日历关联、保存卡片到相册或选择分享目的地时，数据可能进入用户已有的同步服务；操作前说明，默认仅包含最少字段。应用锁也应提供组件与通知隐藏敏感内容的独立选项。

## 9  验收目标与发布风险

以下为产品验收目标，尚非已测结果。研发选定平台后记录参考机型、系统版本和测试数据集，再固化性能阈值。无需远端采集即可完成本地日志和测试统计。

| 指标 | 目标或判定方式 |
| --- | --- |
| 日期正确性 | 公农历、闰年、跨年、时区和生日次日切换用例全部通过 |
| 结构正确性 | 界面、移动、导入和恢复均无法产生第四层、跨本孤儿或循环引用 |
| 恢复完整性 | 标准备份恢复后，事件、寄语、背景和行动记录一致；失败不破坏旧库 |
| 本地可用 | 首次启动和核心操作在飞行模式可完成；不出现登录阻塞 |
| 提醒透明性 | 权限拒绝、系统配额、未安排任务均可解释；不把保存成功等同通知必达 |
| 性能建议 | 2000 个事件和 10000 条行动记录；冷启动可交互 P95 不超过 2 秒，普通保存不超过 300 毫秒 |
| 备份建议 | 100 MB 以内资料的导出和恢复各不超过 30 秒，长任务显示进度并可安全退出 |

高风险集中在农历循环、有限本地通知队列、系统后台限制、破坏性导入和媒体恢复。尤其不能依赖后台应用必定唤醒；长期不打开应用且事件量超出系统安排容量时，只能给出已安排范围和限制，不能承诺所有未来提醒永久必达。

发布必须通过真实设备的关进程、重启、跨日、权限撤销和节电测试。组件按系统规则更新，不承诺每秒刷新。未满足上述限制说明或备份安全的版本，不进入正式发布。平台依据见 S09 至 S14。

已冻结的决定是长期纯本地、不做登录注册及账号体系、不规划云数据库、手动三层事件、单段寄语。下列问题是下一轮产品与技术评审事项，不包含重新引入账号或云存储。

| 待决定事项 | 本稿默认或评审入口 |
| --- | --- |
| 首发平台与最低系统 | 规则同时覆盖 iOS 和 Android，具体支持清单待选型 |
| 农历与闰日规则 | 闰月生日优先普通同月，允许明确选择；闰日默认月末回退，详情可解释 |
| 首页子事件 | 默认主事件参与，子事件手动开启；重点卡片可固定任意层事件 |
| 完整备份保护 | 默认口令加密；普通文本分享为明文并先预览 |
| 日历联动深度 | 先做系统编辑器单向添加与选择性导入；托管持续关联为增强能力 |

### 文档使用方式

本 PRD 用于对齐定位、范围与资源边界；配套的详细需求规格用于交互、数据和测试评审。研发从稳定的需求编号拆分任务，不把待定项或后续能力视为首版已承诺功能。

后续版本继续改进本地使用、备份恢复、日期规则与系统集成。不设置待启用账号入口，不将邮箱认证、云数据库、自动云恢复或在线共同编辑纳入后续规划。
