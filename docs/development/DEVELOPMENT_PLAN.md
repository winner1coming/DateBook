# 后续开发与验收计划

## 当前阶段

本轮只将上一版已生成源码还原为正常Git工程，归档产品/技术资料，补齐运行和检查入口，不借目录调整改写业务逻辑。原始7任务、5波次实现计划保留在 [plan/datebook-initial.md](../../plan/datebook-initial.md)，该文档是历史计划，不是待执行任务状态表。

产品目标完整度、工程构建和运行验收必须分别推进。具体差异见[实现状态](IMPLEMENTATION_STATUS.md)，具体测试用例见[测试计划](../testing/TEST_PLAN.md)。

## 执行顺序

| 阶段 | 工作 | 前置 | 出口 |
|---|---|---|---|
| M0 工程还原 | 保持app/core字节一致，整理docs、保留原件和快照、更新工具路径 | 原始总文件可信可验证 | 源码一致、文档链接、Wrapper校验、85项主机测试通过 |
| M1 正式构建 | 配置JDK17/SDK37，运行Gradle单测/lint/assembleDebug，修复资源/Manifest/DEX差异 | M0 | 对应提交有真实成功构建日志与Debug APK |
| M2 产品差异关闭 | 逐项处理实现状态中的尚未实现项；先确认交互和验收，再补代码和测试 | M1 | 每项有产品决定、实现与回归记录，不静默删需求 |
| M3 设备集成 | 运行35项仪器化；覆盖权限、三级导航、SAF+锁、恢复及系统能力 | M1，相关M2完成 | 模拟器与真机有用例结果，关键路径无P0/P1 |
| M4 稳定性与安全 | 杀进程/断电窗口、恶意备份、性能、TalkBack/大字体、厂商省电 | M3 | 原始数据可恢复；无阻断问题；风险被明确处理 |
| M5 发布候选 | 签名、版本、隐私说明、迁移回归、发布审核 | M2–M4 | 发布清单全部有证据，密钥不进仓库 |

## 每个开发任务的最低内容

写明需求编号、实际问题、目标文件、数据/权限影响、实现方法、测试步骤和判定；改变schema/文件协议需单独设计迁移与兼容。修复测试失败不能靠删除断言、放宽无关约束或假装未运行测试已通过。

## 整理提交的边界

当前 `app/`、`core/`、Gradle配置、Android资源与Room schema从历史快照精确还原。新增/变更仅为README、文档布局、检查工具、CI与归档位置。`python3 tools/verify_repository.py --check-baseline` 仅用于本次目录迁移的一次性字节核对；默认检查和CI不启用该选项，后续业务开发不会被历史快照冻结。源码修改仍需对应需求、评审和回归记录。

Git权限不足时只准备本地工程，不冒充线上已更新；权限就绪后使用正常快进提交，不改写原历史、不强制推送。
