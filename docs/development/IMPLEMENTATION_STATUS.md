# 实现状态与已知差异

本文件按当前源码可观察事实区分“有实现”“主机通过”“待设备验收”和“尚未实现”。PRD/需求规格是目标基线；本次目录化不等于所有P0/P1已经完成，也不缩减产品目标。

## 已有实现

| 范围 | 源码位置 | 当前证据 |
|---|---|---|
| 日期、公农历、生日循环、正倒数与重复 | core/DateEngine、app/LunarAdapter | 业务与真实农历JVM测试 |
| 本/标签/搜索、三级树、移动复制、归档回收 | core/DateBookService | 原子性/关系/状态JVM及SQLite检查 |
| 独立背景与唯一寄语、目标和行动 | core模型与服务、app/ui | 业务测试；页面实际交互待设备 |
| 规范化Room、守卫、幂等、媒体、切库 | app/data、app/schemas | 真Room/KSP生成、API编译、主机SQLite；设备事务/恢复待验 |
| JSON/CSV与认证全备份、合并/替换 | core/FileCodec、app/ui/AppViewModel | 文件协议/攻击样例/密码互通JVM测试 |
| 提醒、组件、日历、卡片、锁与任务 | app/platform、app/ui | 实际Android API编译；系统效果和安全路径待真机 |

“有源码”不表示系统效果已验证。主机85项测试通过；35项仪器化只是代码编译通过，没有设备执行。正式APK全流水线仍待M1，详见[测试报告](../testing/TEST_REPORT.md)。

## 已确认的技术调整

- 原TD的更多物理模块收敛为core/app两个模块，内部仍按data/platform/ui分包；构造器注入代替Hilt，见[ADR](../decisions/ADR.md)。
- KSP固定为2.3.10，旧候选与AGP9内建Kotlin配置不兼容的问题已复现并修正。
- 当前顺序调整是“上移/下移”按钮，不是拖拽；文档需区分等效功能与原交互形式。
- 系统日历使用用户确认的一次性添加/选择复制；不提供持续托管双向同步。

## 不能标为已完成的产品差异

以下是本轮文档核对发现的差异，非完整正式审计；没有因为整理仓库而擅自补做或从PRD删除。接手时仍需逐项完整覆盖核查。

| 需求目标 | 当前代码情况 | 后续动作 |
|---|---|---|
| TOOL02 周一至周五工作日计算及节日模板 | 日期工具有日期差、N天后及公历转农历；没有工作日计算入口和相关算法 | 保留“未含调休”文案，补算法/页面/边界测试；模板范围产品确认 |
| LOC01 首次本地说明和双入口、LOC03资料库名称编辑 | 直接进入首页，可在工具中导入；没有专门首次引导和改名入口 | 补首次体验与资料库设置用例 |
| LOC03媒体占用、最后完整备份时间与备份后变更状态 | 设置显示本和事件数、可查看任务；未提供完整的备份新旧状态指标 | 定义设备元数据与展示，避免误报可恢复性 |
| BOOK01 本归档与拖拽顺序 | 有事件归档、本新建/改名/封面/删本、上下按钮排序；无本自身归档状态 | 明确本归档语义和交互，必要时设计迁移 |
| MEDIA字体/字号等完整样式控制 | 模型保留fontKey，有背景/遮罩/文字明暗；没有完整字体字号编辑入口 | 确定离线字体及渲染一致性，再补UI/卡片/组件测试 |
| NOT按事件的已安排/部分失败等详细诊断 | 有规则、权限能力和重建；没有完整逐事件安排状态面板 | 从设备票据/队列形成诊断模型，不能只以开关代替安排成功 |
| CSV预览逐行勾选与更完整冲突选择 | 有逐行错误、有效项预览与整体确认；未提供逐行勾选控制 | 补选择模型及全成全败/跳过规则测试 |
| 平台锁屏组件、性能和完整无障碍 | 仅有平台声明/基础语义与测试规划，没有覆盖设备验收 | 按设备支持矩阵实测，结果未通过前不承诺可用 |

## 当前不在范围内

登录/邮箱验证/云库/实时共享/iOS/服务器推送已被用户明确排除，不是“还没实现”的缺陷。自动生成百日千日、多条小纸条也不加入后续任务。以上已知差异应进入开发计划，不与明确排除项混淆。
